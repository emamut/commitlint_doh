Editor & Validador de Commits Convencionales

Escribe commits claros, estandarizados y sin esfuerzo con validación sintáctica en tiempo real.

Construir Mensaje

0 / 50
Modo imperativo ("add" en vez de "added"), sin mayúscula inicial y sin punto final.

commit-message.txt Esperando... 
your commit message will appear here
message to be linted
No se puede crear el commit por las siguientes razones:
  • Debes seleccionar un tipo de commit válido (ej: feat, fix, chore, docs).
  • Debes ingresar una descripción corta (subject) después de los dos puntos.

Estructura Rápida

<tipo>(<ámbito>)[!]: <descripción>
[cuerpo opcional]
[footer(s) opcional(es)]

Estándar Conventional Commits

Tipo Descripción SemVer Impact
feat Nueva funcionalidad o característica para el usuario final. MINOR
fix Solución a un defecto o fallo detectado en la aplicación. PATCH
docs Cambios exclusivamente en documentación (README, manuales, docstrings). Ninguno
refactor Reestructuración de código sin alterar comportamiento externo ni corregir bugs. PATCH
perf Modificación que optimiza el rendimiento o velocidad de procesamiento. PATCH
test Añadir o corregir pruebas unitarias, de integración o suites de test. Ninguno
build Cambios en dependencias externas o herramientas de compilación/bundling (npm, gradle). Ninguno
ci Ajustes en integración continua (GitHub Actions, Netlify, Travis, GitLab CI). Ninguno
chore Tareas rutinarias de mantenimiento que no afectan el código de producción. Ninguno
! (Breaking) Cualquier tipo con signo de exclamación ! indica un cambio disruptivo. MAJOR
¿Por qué la regla de los 50 caracteres?

La primera línea es el resumen de la vista compacta en herramientas como git log --oneline, GitHub y terminales. Mantenerla en 50 caracteres garantiza que sea legible sin truncamiento.

¿Por qué envolver a 72 caracteres?

Git formatea las entradas con una sangría predeterminada en los comandos de consola. Un límite de 72 caracteres evita saltos de línea irregulares en terminales estándar de 80 columnas.

¿Por qué evitar barras invertidas (\)?

Las contrabarras (\) pueden interpretarse como caracteres de escape en scripts de CI/CD, shells o parsers de Markdown, provocando errores inesperados en el historial.

¿Por qué tiempo imperativo presente?

Sigue la propia convención de Git (por ejemplo: "Merge branch..."). Al leer el commit se completa la frase: "Si se aplica este commit, este cambio va a [tu descripción]".

Privacidad y Uso Offline

Commitlint_D'oh! es una herramienta open-source diseñada para escribir commits conformes con el estándar sin requerir configuraciones adicionales en tu entorno de desarrollo. Todo se ejecuta 100% en tu navegador de forma privada (sin enviar datos a ningún servidor externo).
